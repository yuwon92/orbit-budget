# Orbit — 오늘의 예산

항목별 예산을 정해두고, **오늘 얼마를 쓸 수 있는지** 알려주는 개인 예산 웹앱.

기존 가계부 앱은 과거를 기록해서 한 달 뒤에 "식비가 많았네"를 알려준다. 하루 예산만 계산해주는 앱은 항목별 관리가 없다. 이 앱은 둘 다 한다.

서버도 로그인도 없다. 모든 데이터는 브라우저에만 저장된다.

## 핵심 아이디어

홈 화면에 숫자를 두 개 보여준다.

- **오늘 예산** — 아침에 정해지고 하루 종일 변하지 않는 기준선
- **남은 금액** — 지출할 때마다 실시간으로 줄어드는 값

기준선이 고정되어야 초과 여부를 인지할 수 있다. 잔여 금액만 있으면 그냥 줄어드는 숫자일 뿐이다. 초과하면 남은 금액이 음수로, 빨간색으로 표시된다.

## 화면

| 화면 | 내용 |
|---|---|
| 홈 | 오늘 예산 / 남은 금액, 카테고리별 진행률, 오늘 내역 |
| 달력 | 날짜별 지출·수입·예정 거래, 날짜 선택 시 상세 |
| 거래 내역 | 전체 거래를 날짜별로 묶어서 표시, 삭제 |
| 설정 | 카테고리 관리, 반복 거래, CSV 내보내기, 테마 전환 |

## 계산 로직

앱의 핵심. [`src/lib/budget.ts`](src/lib/budget.ts)에 UI와 분리된 순수 함수로 구현되어 있다.

```
가용액    = 이번 달 총수입 − 이미 발생한 지출(오늘 이전)
오늘 예산 = (가용액 − 남은 기간의 예정 지출 − 예비비) ÷ 남은 일수
남은 금액 = 오늘 예산 − 오늘 이미 쓴 금액
```

- **총수입**에는 날짜와 금액이 확정된 예정 수입(알바비 등)도 포함한다.
- **남은 일수**는 오늘을 포함해 이번 달 마지막 날까지.
- 나눗셈 결과는 `Math.floor()`로 **내림**한다. 올림하면 실제보다 많이 쓸 수 있다고 착각하게 된다.
- 카테고리 예산을 다 쓰지 않아도 차액을 따로 이월하지 않는다. 위 공식이 실제 지출 기준으로 계산하므로, 아끼면 자동으로 가용액이 늘고 다음 날 오늘 예산이 올라간다.

오늘 지출을 계산에서 제외하기 때문에, 지출을 입력해도 오늘 예산 기준선은 움직이지 않는다. 별도의 일일 캐시가 필요 없는 이유다.

### 검산

돈 계산은 그럴듯해 보여도 틀릴 수 있어서 검산 스크립트를 붙여뒀다.

```bash
npm run verify
```

총수입·자유 예산·오늘 예산·반복 거래 월말 보정·CSV 생성을 한 번에 확인한다. 계산 로직을 고칠 일이 있으면 이 스크립트가 회귀 테스트 역할을 한다.

## 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | React + Vite | |
| 언어 | TypeScript | 금액 계산에서 타입 실수를 막아줌 |
| 저장소 | Dexie (IndexedDB) | localStorage는 용량 한계와 문자열 변환 문제가 있음 |
| 날짜 | date-fns | |
| 아이콘 | lucide-react | |
| 설치 | vite-plugin-pwa | 홈 화면에 추가해 앱처럼 실행 |
| 배포 | Vercel | main 브랜치 푸시 시 자동 배포 |

스타일은 프레임워크 없이 [`src/index.css`](src/index.css) 한 파일에서 CSS 변수로 관리한다. 라이트/다크 테마는 같은 브랜드 컬러를 쓰고 밝기와 대비만 조절한다.

## 시작하기

```bash
npm install
npm run dev      # 개발 서버
npm run build    # 타입 검사 + 프로덕션 빌드
npm run preview  # 빌드 결과 확인
npm run verify   # 계산 로직 검산
```

PWA 아이콘을 다시 만들려면 `node scripts/gen-icons.ts`. 외부 라이브러리 없이 PNG를 직접 인코딩한다.

## 데이터 저장

모든 데이터는 **브라우저의 IndexedDB**에만 저장된다. 서버로 전송되지 않고, 기기 사이에서 동기화되지도 않는다. PC와 폰은 서로 다른 데이터를 갖는다.

주의할 점이 있다.

- 브라우저 데이터를 지우면 함께 사라진다.
- iOS 사파리는 7일간 방문하지 않으면 저장소를 비운다. **홈 화면에 추가해 설치하면 이 규칙에서 제외된다.**
- 앱 시작 시 `navigator.storage.persist()`로 자동 삭제 방지를 요청하지만, 승인 여부는 브라우저가 정한다.

**백업 수단은 설정 → 데이터 내보내기(CSV)뿐이다.** 주기적으로 내보내 두는 것을 권한다. CSV는 BOM을 붙여 저장하므로 엑셀에서 한글이 깨지지 않는다.

## 반복 거래

매달 정해진 날짜에 발생하는 구독료나 정기 수입을 등록해두면, 앱을 열 때 이번 달 예정 거래가 자동으로 만들어진다. 규칙마다 마지막 생성 월을 기록해서 중복 생성되지 않는다.

`dayOfMonth`가 그 달의 마지막 날보다 크면 마지막 날로 보정한다. 31일 규칙은 9월에 30일, 2월에 28일로 들어간다.

규칙을 수정하거나 삭제하면 이번 달의 **아직 날짜가 지나지 않은** 예정 거래만 다시 만들어진다. 이미 발생한 거래는 건드리지 않는다.

## 디자인

행성(Planet)을 브랜드 모티프로 쓰되, 전체적으로는 차분한 금융 앱을 유지한다. 대략 금융 앱 80%에 행성 정체성 20%.

- 행성 그래픽은 홈 히어로와 빈 상태에만 사용한다. 금융 수치보다 강하게 보이면 안 된다.
- 기능 아이콘은 line icon(lucide)으로 통일하고, 장식은 SVG/CSS 도형으로 만든다.
- 이모지는 앱 전체에서 사용하지 않는다.
- 금액에는 `font-variant-numeric: tabular-nums`를 적용해 숫자 폭이 흔들리지 않게 한다.
- 상태 구분은 색 점과 부호(+/−)로 표현한다. 글자에 배경색을 깔지 않는다.

진행률 색은 기본 파랑, 80% 이상 주황(`#e7b96a`), 100% 초과 코랄 레드(`#ef7777`).

## 아직 안 된 것

- **예비비 설정** — 계산 로직은 예비비를 지원하지만 값을 입력하는 화면이 없다. 현재는 항상 0으로 계산된다. (설정 화면의 안내 문구도 실제 값이 아니다)
- **거래 내역 검색·필터** — UI만 있고 동작하지 않는다.
- **홈의 "전체 보기" 버튼** — 연결되어 있지 않다.
- **거래 수정** — 삭제 후 다시 입력해야 한다.

의도적으로 범위 밖에 둔 것: 계좌 자동 연동, 클라우드 동기화·로그인, 통계 리포트와 차트, 다중 통화.
